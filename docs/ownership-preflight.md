# فحص تمهيدي لملكية المدارس — المرحلة 1

آخر تحديث: 27 أكتوبر 2026. هذه أداة **تجريبية للقراءة فقط** تجمع أعدادًا للمراجعة، وليست أداة تسوية أو نسخة احتياطية أو استعادة أو اعتمادًا للترقية. استُخدمت هنا بيانات اصطناعية فقط. تظل المراجعة البشرية الأمنية وخطة التعامل مع البيانات القديمة مطلوبة؛ لا يمنح هذا الفحص موافقة على الدمج أو الإطلاق.

## طريقة الاستخدام الآمنة

الأداة في `scripts/school_ownership_preflight.py` تستخدم مكتبة Python القياسية وSQLite فقط. لا تُشغَّل على قاعدة حية أو ملفها مباشرة، ولا على بيانات حقيقية ضمن هذه التجربة. تُستخدم فقط على **نسخة مستقلة، غير متصلة ولا يكتب إليها أحد، أُنشئت وتحققت سلامتها بمسار نسخ احتياطي معتمد**. لا يثبت وجود ملف منفرد أن محتوياته مكتملة؛ قد يكون ملف `.db` منسوخًا دون WAL اللازم.

مثال صياغة لملف اصطناعي غير متصل عند توفر Python 3.11 أو أحدث:

```bash
python3 scripts/school_ownership_preflight.py /path/to/synthetic-offline-snapshot.db
python3 scripts/school_ownership_preflight.py --help
```

- تُفتح النسخة باستخدام `mode=ro` و`immutable=1` مع `query_only`، وتُرفض الرموز غير المباشرة للملف والملفات المصاحبة `-wal` أو `-shm` أو `-journal` حتى إن كانت فارغة. **لا تحذف هذه الملفات لتجاوز الرفض**؛ أعد إنشاء نسخة متسقة بوسيلة مناسبة وتحقق منها.
- وضع `immutable` لا يقرأ WAL ولا يقفل القاعدة. الفحص يقارن هوية الملف وحجمه وأوقات تغيّره قبل القراءة وبعدها ويرفض بعض حالات التغيير، لكنه **لا يستطيع إثبات غياب كاتب متزامن أو اكتشاف WAL مفقود من نسخة غير مكتملة أو كل حالات السباق**. مسؤول تشغيل الفحص يجب أن يتحقق من استقلال النسخة ومصدرها قبل فتحها.
- يُطبع JSON بأعداد عامة فقط، دون أسماء أو معرّفات أو محتويات سجلات أو مسار الملف. مع ذلك قد تكون الأعداد نفسها حساسة، خصوصًا للمجموعات الصغيرة؛ لا تنشرها أو تخزنها في سجلات عامة دون موافقة وسياسة خصوصية مناسبة.
- رمز الخروج `0` يعني فقط اكتمال الحسابات، **حتى عند وجود مؤشرات تعارض أو مخالفات مفاتيح أجنبية**. `2` يعني رفض الإدخال أو فشل الفحص، دون تقرير جزئي أو تفاصيل قاعدة البيانات في الخطأ. ليس هناك حقل يعلن أن الترحيل آمن.

## معنى النتائج

| القسم | ما يبيّنه وما لا يبيّنه |
| --- | --- |
| `schema` | `legacy` قبل ترحيل الملكية أو `owned` بعده. يُرفض تاريخ ترحيلات غير مطابق للحالتين المعروفتين، أو غياب الأعمدة الضرورية، أو وجود بعض أعمدة الملكية فقط. لا يفحص الأداة تطابق كل تفاصيل المخطط أو اكتشاف جميع التخصيصات. |
| `totals` | أعداد الطلاب والمعلمين والدورات والتسجيلات وروابط أولياء الأمور وسجلات الحضور والسلوك والقرآن؛ ليست قائمة موارد ولا توصية بملكيتها. |
| `ownership` | قبل الترقية يكون `current_unassigned` مساويًا `null` لأن الأعمدة غير موجودة، ويعرض `projected_unassigned_after_upgrade` عدد الصفوف الحالية التي ستبقى بلا ملكية وفق الترحيل الحالي ودون أي تغييرات أخرى. بعد الترقية تُعرض القيم الفعلية `current_unassigned` ويصبح التوقع `null`. |
| `integrity` | `quick_check` لسلامة SQLite، وعدد نتائج `foreign_key_check` للمفاتيح المعرّفة بالفعل دون تفاصيل الصفوف. لا يثبت صفر المخالفات أن جميع القيود المتوقعة موجودة، ولا يغني عن `integrity_check` الكامل أو التحقق التشغيلي. |
| `review` | مؤشرات مجمّعة مثل الطلاب ذوي تسجيلات في أكثر من مدرسة، أو الطلاب/المعلمين ذوي عضويات فعالة في أكثر من مدرسة، أو المعلمين ذوي دورات دون عضوية فعالة، أو التسجيلات ذات السنوات غير المتسقة، أو روابط أولياء بلا عضوية فعالة في مدرسة أحد التسجيلات، أو مجموعات حضور للطالب والتاريخ نفسيهما. |
| `post_migration_review` | بعد الترحيل فقط: أعداد التسجيلات والشعب وروابط الأولياء غير المطابقة لبعض شروط الملكية، وأعداد السجلات التي تختلف مدرستها عن مدرسة الطالب أو لها مدرسة والطالب غير مملوك. تبقى السجلات ذات المدرسة الفارغة ضمن `current_unassigned`. |

التسجيلات في المؤشرات تشمل **كل الحالات والتاريخ**، لا النشطة فقط؛ تعدد المدارس قد يعكس انتقالًا مشروعًا أو خطأً، ولا يثبت وحده تسريبًا. «العضوية الفعالة» تعني `IsActive = 1` للعضوية ولا تتحقق هذه الأداة من فعالية المدرسة. مؤشر الولي يحتسب الرابط إذا غابت عضويته عن **أي** مدرسة من مدارس تسجيلات الطالب، لا أنه ثبت وصوله إليها. قد تتداخل المؤشرات ولا يجوز جمعها كعدد أشخاص متميزين. لا تقترح الأداة مدرسةً لصف أو تُصدر معرّفات للمعالجة.

مجموعات الحضور المكررة قد تمنع إعادة إنشاء قيد `(StudentId, Date)` القديم عند التراجع، لكن غيابها لا يضمن نجاح التراجع: إزالة أعمدة الملكية تُفقد قيمها أيضًا. استعادة نسخة ما قبل الترقية تفقد الكتابات اللاحقة ما لم تُعالَج بخطة منفصلة معتمدة.

## الدليل والحدود

- محليًا: `/tmp/smartschool-venv-probe/bin/python -m pytest -q tests/test_school_ownership_preflight.py` من مجلد `backend` نجح بـ **21 اختبارًا اصطناعيًا**؛ تشمل الحالات قبل الترحيل وبعده، وWAL النشط، والملفات المصاحبة، ومخططًا جزئيًا أو مجهولًا، والتسرب في الأخطاء، ورفض الكتابة، وتغير الملف أثناء الفحص. نجحت مجموعة Python المحلية الكاملة بـ **55 اختبارًا وتحذيرين** في Python 3.11 بتبعيات جزئية.
- [CI لطلب السحب 40551682150](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40551682150) على `17f2364` أنشأ قاعدة مؤقتة بالترحيل القديم الفعلي لـEF، وأدخل بيانات اصطناعية، وفحصها قبل الترقية وبعد ترحيل الملكية الفعلي، وقارن المؤشرات ومجاميع الملكية وبصمة الملف قبل الفحص وبعده. نجحت خطوة EF، ونجح **84/84 اختبار .NET** وعشرة اختبارات إلزامية؛ نجحت مهمتا Python وExpo. اختبار `--help` وحارس السيناريوهات أُضيفا بعد هذا التشغيل ويجب فحص نتيجة CI الأحدث لهما.
- لا تغطي الأداة كل حالات الصلاحيات أو فساد المخططات المخصصة أو أساليب SQLite غير القياسية أو الأداء على أحجام كبيرة أو التشفير أو النقل أو الأعطال. لا تحل محل فحص بشري للروابط الفردية أو إجراء مراجعة محكوم الصلاحية.
- لم تُستخدم قاعدة إنتاجية أو نسخة منها، ولم تُنشأ أو تُختبر عملية تسوية فردية أو تحديث جماعي. لتجربة النسخ والاستعادة الاصطناعية راجع [تجربة الترحيل](migration-rehearsal.md).
