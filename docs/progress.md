# تقدم مشروع SmartSchool

آخر تحديث: 27 أكتوبر 2026.

هذا السجل يتتبع مراحل خطة SmartSchool المرفقة. تعني حالة «مؤجلة» أن المرحلة لم تُنفّذ أو تُتحقق وفق معايير هذه الخطة، ولا تعني بالضرورة عدم وجود شيفرة أولية تخصها.

## حالة المراحل

| المرحلة | الحالة | الوضع الحالي |
| --- | --- | --- |
| 0 — شبكة الأمان والاختبارات وCI | **مكتملة وفق معيار القبول** | اختبارات API وPython وفحوص Expo تعمل في CI؛ استبعاد بناء MAUI موثّق أدناه. |
| 1 — عزل بيانات المدارس | **تحققت آليًا؛ بانتظار مراجعة بشرية** | نجحت اختبارات العزل والترحيل في CI. لا تُدمج قبل المراجعة البشرية وخطة التعامل مع البيانات القديمة. |
| 2 — الحسابات والجلسات | مؤجلة | يلزم معالجة فرادة أسماء المستخدمين، وتحديد المحاولات، وإبطال الجلسات وتجديدها المتزامن. تتطلب مراجعة بشرية قبل الدمج. |

| 6 — دورة إدارة المدرسة | مؤجلة | يلزم استكمال الروابط والعمليات وقواعد المجال تحت عزل المدارس. |

| 9 — الذكاء الاصطناعي | مؤجلة حتى اكتمال 0–8 | الخدمة الحالية تجريبية ومنفصلة؛ لا تُربط ببيانات المدرسة قبل توحيد الهوية والصلاحيات. |

## المرحلة 0: المنجز والأدلة

- استُخدم مشروع `SmartSchoolAPI.Tests` القائم مع `WebApplicationFactory` وقاعدة SQLite معزولة في الذاكرة لكل مصنع، وأُضيفت أدوات لإنشاء مدرستين ومستخدمين بأدوار مختلفة.
- أُصلح اختبار رفض JWT في Python، وأُضيف تحقق معاكس يفشل عندما يُستبدل المتحقق بآخر يقبل الرمز غير الصالح.
- يشغّل CI بناء API واختباراته وترحيلات EF، واختبارات Python، وفحوص TypeScript وLint وتصدير Expo. تتحقق بوابة TRX من وجود اختبارات منفّذة وناجحة، ومن نجاح اختباري التكامل الجديدين بالاسم.
- [تشغيل CI رقم 40533109774](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40533109774) على الالتزام `26989a1` نجح: **51 اختبار .NET منفّذ وناجح**، بما فيها حالتا التكامل المطلوبتان؛ كما نجحت مهام Python وExpo. هذا دليل المرحلة صفر قبل تغييرات المرحلة الأولى.
- التفاصيل والأوامر والنتائج الفعلية، بما فيها اختبار Python المحلي وفحص JWT المعاكس، موثّقة في [تقرير المرحلة صفر](../STAGE_0_TESTING.md).

### ما لم يُتحقق منه

- لم يتوفر .NET SDK محليًا؛ فشل تنزيله في بيئة العمل، لذا كان تحقق .NET على CI لا محليًا.
- لم يُبنَ MAUI محليًا أو في CI. تشير قراءة الشيفرة إلى استخدام `QuranRecordDto` دون تعريفه؛ هذه ملاحظة تحليل ثابت وليست نتيجة بناء فعلية. استبعاد MAUI مؤقت وموثّق في تقرير المرحلة صفر.
- نجاح تصدير Expo لا يثبت عمل تسجيل الدخول على المتصفح أو جهاز فعلي.

## المرحلة 1: عزل المدارس

- أُضيفت اختبارات HTTP فعلية بقاعدتي مدرستين منفصلتين قبل إصلاح التفويض. [CI رقم 40539449716](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40539449716) أثبت 16 إخفاقًا متوقعًا؛ أبرزها نجاح تسجيل طالب أجنبي، وقراءة Student 360/القرآن والكتابة بعد تسجيل متعارض، وإضافة معلم أجنبي. نجحت مهام Python وExpo في التشغيل نفسه.
- أكدت اختبارات إضافية قبل الإصلاح روابط أولياء عابرة للمدارس، وتعارض سجل حضور مجهول المصدر، وغياب مدرسة السجل الجديد. راجع [جدول التدقيق](isolation-audit.md) للأدلة وتغطية كل endpoint.
- أُضيف نطاق مركزي وملكية صريحة، واختبار لترقية قاعدة قديمة اصطناعية. يحفظ الترحيل الصفوف القديمة لكنه يترك ملكيتها غير معروفة ويمنع ظهورها للمدارس إلى حين مراجعة بشرية؛ لذلك يتطلب التطبيق على بيانات قائمة خطة تسوية واستعادة، ويحجب البيانات القديمة تشغيليًا إلى حين ذلك. [قرارات الترحيل والنقل](decisions.md).
- [CI رقم 40542144064](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40542144064) على الالتزام `4c7aa01`: بُنيت API واختباراتها، وطابق الترحيل النموذج وطُبّق، ونجح **81 من 81 اختبار .NET**، وتحققت البوابة من سبعة اختبارات مطلوبة بالاسم، ومنها اختبار ترقية البيانات القديمة. نجحت مهمتا Python وExpo أيضًا. لم يُشغَّل .NET محليًا.
- أُعيد تشغيل `python -m pytest -q` محليًا تحت Python 3.11 وبتبعيات اختبار جزئية: **34 نجحت وتحذيران**؛ هذه البيئة ليست مطابقة لبيئة Python 3.12 الكاملة في CI.
- المراجعة البشرية الأمنية وخطة تسوية البيانات القديمة مطلوبة قبل أي دمج أو إطلاق؛ لم يحدث دمج.

## المخاطر المتبقية

- **عزل المدارس:** نجحت السيناريوهات المختبرة بعد الإصلاح، لكن ذلك لا يثبت أمان جميع الحالات الممكنة. يلزم تدقيق بشري وخطة عملية لتسوية البيانات القديمة المحجوبة قبل الإطلاق.
- **الحسابات والجلسات:** تشير مراجعة الشيفرة إلى غياب قيد فرادة اسم المستخدم، وحد محاولات مشترك، واستمرار صلاحية رمز الدخول بعد تسجيل الخروج حتى انتهاء مدته.
- **بيانات التجربة:** أظهر اختبار سابق على قاعدة مؤقتة أن سكربت التجربة يكتب كلمات مرور بنص صريح ويستخدم دورًا لا يطابق أدوار API.
- **الاتصال والواجهات:** إعدادات الاتصال الافتراضية ليست إعدادات إنتاج آمنة، وتوافق `expo-secure-store` ودعم الويب يحتاجان معالجة. لم تُختبر وظائف الهاتف من البداية للنهاية.
- **الذكاء الاصطناعي:** الخدمة التجريبية لا تشارك هوية المدرسة وصلاحياتها؛ لا تُستخدم للوصول إلى بيانات الطلاب قبل المرحلة 9.

## قرارات ومراجعة

- قرار الواجهة الرئيسية معلّق لصاحب المشروع قبل المرحلة 5؛ المقترح الافتراضي هو Expo واجهة رئيسية وMAUI واجهة ثانوية يُصلح بناؤها.
- تُجرى التغييرات على فرع الجلسة الحالي؛ لا يُنشأ فرع مستقل لكل مرحلة. تتطلب المرحلتان 1 و2 مراجعة بشرية قبل الدمج.
- بدأت المرحلة 1 بطلب المستخدم بعد توثيق المرحلة صفر. لا تُبدأ المراحل اللاحقة ضمن هذا الطلب.
