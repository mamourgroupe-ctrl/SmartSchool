# تدقيق عزل المدارس — المرحلة 1

آخر تحديث: 27 أكتوبر 2026. يراجع هذا الجدول جميع الـcontrollers والخدمات في `SmartSchoolAPI` والمسارات المعرّفة في `Program.cs`. «يتحقق» يصف آلية الشيفرة بعد التعديل؛ لا يعني بمفرده أن كل تركيب ممكن اختُبر. للاستثناءات التشغيلية والبيانات القديمة وسياسة النقل انظر [القرارات](decisions.md).

`ISchoolScope` يستخرج هوية الطلب الموثّق ويطبق قيود العضوية والملكية والعلاقة. المشرف العام مستثنى عمدًا من ترشيح القراءة ليتمكن من مراجعة جميع المدارس والصفوف المحجوبة. المعرّف في المسار يحدد المورد المطلوب ولا يختار صلاحيات المنفذ. القوائم تعود `200` مع استبعاد الموارد غير المصرح بها؛ الطلبات الصحيحة على موارد أجنبية محددة تعود عادةً `404`، وتعود `403` عند منع الدور أو غموض مدرسة إنشاء الحساب. قد تعود `400` للمدخلات غير الصالحة قبل فحص المورد.

## جدول نقاط الوصول

| نقطة الوصول | تحقق نطاق المدرسة بعد التعديل |
| --- | --- |
| `POST /api/auth/login` | غير متعلق ببيانات مدرسة: يتحقق من بيانات الحساب ويصدر هوية موقّعة؛ لا يمنح مدرسة من العميل. |
| `POST /api/auth/refresh` | غير متعلق ببيانات مدرسة: يتحقق من رمز التجديد ويعيد إصدار هوية الحساب. |
| `POST /api/auth/logout` | للجلسة الموثّقة فقط؛ يُبطل رموز تجديد المستخدم الحالي، ولا يقبل مستخدمًا من العميل. |
| `GET /api/students` | نعم: `ISchoolScope.Students` للمدير والمعلم والولي والطالب؛ المشرف العام شامل. الطالب غير المعيَّن يرى ملفه الأساسي فقط. |
| `POST /api/students` | نعم: مشرف عام/مدير بعضوية فعالة واحدة فقط؛ ينشئ الطالب وعضويته ومدرسته ضمن معاملة، دون مدرسة من الجسم. |
| `GET /api/teachers` | نعم: `ISchoolScope.Teachers` بالملكية والمدرسة وعلاقات الطالب؛ المشرف العام شامل. |
| `POST /api/teachers` | نعم: عضوية فعالة واحدة للمنفذ، وإنشاء المعلم وملكيته وعضويته ضمن معاملة. |
| `GET /api/courses` | نعم: الدورات عبر المعلمين المرئيين في `ISchoolScope.Courses`؛ المشرف العام شامل. |
| `POST /api/courses` | نعم: المشرف العام أو المدير؛ المعلم يجب أن يكون ظاهرًا ومملوكًا لمدرسة يملك المنفذ إدارتها. |
| `POST /api/organizations` | للمشرف العام فقط؛ ينشئ مدرسة جديدة، ولا يمنح مدير مدرسة صلاحية إنشاء مدرسة أخرى. |
| `POST /api/organizations/{organizationId}/members` | نطاق المدرسة من قاعدة البيانات؛ إضافة حساب موجود للمشرف العام فقط، مع منع إسناد طالب/معلم مملوك أو له تاريخ مجهول إلى مدرسة أخرى. |
| `POST /api/organizations/{organizationId}/academic-years` | نعم: يتحقق `CanAdminOrganizationAsync` من صلاحية إدارة المدرسة الفعالة. |
| `POST /api/academic-years/{academicYearId}/terms` | نعم: تُستخرج مدرسة السنة من قاعدة البيانات وتُفحص صلاحية إدارتها. |
| `POST /api/academic-years/{academicYearId}/classes` | نعم: تُستخرج مدرسة السنة من قاعدة البيانات وتُفحص صلاحية إدارتها. |
| `POST /api/classes/{schoolClassId}/sections` | نعم: تُفحص مدرسة الفصل، ويجب أن يكون المعلم المختار مملوكًا للمدرسة نفسها وله عضوية فعالة؛ المعلم الأجنبي `404`. |
| `POST /api/enrollments` | نعم: مدرسة الفصل الدراسي والشعبة والسنة متطابقة؛ الطالب مملوك للمدرسة نفسها. يُرفض الطالب الأجنبي أو القديم غير المحسوم حتى للمشرف العام، باستثناء إسناد أولي لحساب بلا تاريخ. |
| `POST /api/students/{studentId}/guardians` | نعم: مدير الطالب أو المشرف العام بعد التحقق من ملكية الطالب وتسجيله في المدرسة نفسها؛ يُنشأ رابط الولي وعضويته في المدرسة ضمن معاملة. |
| `GET /api/students/{studentId}/360` | نعم: الطالب المرئي أولًا، ثم تسجيلات وروابط أولياء وسجلات مرشَّحة عبر النطاق المركزي؛ لا تُعرض السجلات مجهولة المدرسة أو غير المطابقة لغير المشرف العام. |
| `POST /api/students/{studentId}/attendance` | نعم: مدير الطالب أو معلم شعبته أو مشرف عام؛ مدرسة السجل مأخوذة من الطالب المصرّح به، والفرادة لكل مدرسة/طالب/تاريخ. |
| `POST /api/students/{studentId}/behavior` | نعم: إدارة الطالب مطلوبة، وتُشتق مدرسة السجل من الطالب المصرّح به. |
| `POST /api/students/{studentId}/quran` | نعم: إدارة الطالب مطلوبة، وتُشتق مدرسة السجل من الطالب المصرّح به. |
| `GET /api/students/{studentId}/quran` | نعم: التحقق من مشاهدة الطالب وترشيح السجلات بمطابقة مدرستي السجل والطالب. |
| `GET /api/students/{studentId}/quran/summary` | نعم: يستخدم السجلات المرشحة نفسها قبل حساب الملخص. |
| `GET /` | عام ويعيد نص حالة ثابتًا فقط؛ لا يصل إلى بيانات مدرسة. |
| `GET /__test__/throw` | موجود فقط في بيئة `Testing` للتحقق من معالج الخطأ العام؛ لا يُعرّض بيانات المدرسة. |

لا توجد حاليًا نقاط `GET` منفردة للطالب أو المعلم أو الفصل، ولا `PUT` أو `PATCH` أو `DELETE` لهذه الموارد، ولا endpoint لنقل الطالب. لم تُختَرع مسارات اختبار لهذه العمليات غير الموجودة.

## مراجعة الخدمات

- `SchoolScope` / `ISchoolScope`: مركز استعلامات الطلاب والمعلمين والدورات والتسجيلات وروابط أولياء الأمور والحضور والسلوك والقرآن، والتحقق من العضوية والملكية وإدارة الطالب. الصف غير المملوك أو السجل غير المطابق محجوب لغير المشرف العام. المعلم والولي بحاجة أيضًا إلى علاقة المدرسة والطالب، لا إلى معرفهما فقط.
- `Stage1AccessService`: يفوض صلاحيات إدارة المدرسة والطالب والمعلم إلى النطاق المركزي. استعلامات تحديد مدرسة السنة/الشعبة تساعد في معرفة مالك المورد ولا تمنح الصلاحية وحدها؛ يجب أن يتبعها التحقق من `CanAdminOrganizationAsync`.
- `Student360Service`: يتحقق من رؤية الطالب ويجلب كل المجموعات عبر النطاق المركزي. يحجب السلوك `INTERNAL` عن الولي والطالب؛ المشرف العام قادر على مراجعة السجلات المحجوبة.
- `PasswordService` و`RefreshTokenService` لخدمات الاعتماد تحت `Security` لا تختاران مدرسة ولا تستعلمـان عن سجلات الطلاب. مراجعة الجلسات وفرادة الحسابات الأوسع تخص المرحلة 2.

## دليل وحدود التحقق

- قبل الإصلاح، [CI 40539449716](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40539449716) بنى API واختباراته ونفذها وأظهر **16 إخفاقًا** مقصودًا؛ منها تسجيل طالب مدرسة أخرى، وقراءة/كتابة سجلاته بعد تسجيل متعارض، وإضافة معلم أجنبي. نجح Python وExpo في التشغيل نفسه.
- أكّد [CI 40540331248](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40540331248) أيضًا فشل اختبار رابط ولي أمر عابر للمدارس واختبار تعارض الحضور القديم. وأكد [CI 40540961842](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40540961842) ظهور اسم ولي أجنبي عبر رابط قديم، بينما بيّن [CI 40541175317](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40541175317) أن مدرسة السجل الجديد كانت `NULL` قبل الإصلاح.
- اختبارات API تستخدم SQLite معزولة وبيانات اصطناعية، ويتضمن اختبار المرحلة 0 تسجيل دخول حقيقيًا لأدوار المدارس. لا يستبدل ذلك اختبار ترقية نسخة من قاعدة بيانات حقيقية بعد تنقيحها أو المراجعة الأمنية البشرية.
- لا يوجد SDK ‏.NET محلي في بيئة العمل؛ التنفيذ الفعلي لـ.NET يتم في GitHub Actions. يبقى التحقق النهائي ونتيجته موثقين في [التقدم](progress.md).
