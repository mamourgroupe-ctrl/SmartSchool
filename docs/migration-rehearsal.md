# تجربة ترحيل الملكية والنسخ والاستعادة — المرحلة 1

آخر تحديث: 27 أكتوبر 2026. هذه **تجربة على بيانات اصطناعية فقط** لتجهيز المراجعة، وليست موافقة بشرية أو خطة تشغيل إنتاجية معتمدة. لا توجد أداة لتسوية ملكية البيانات القديمة، ولم تُستخدم قاعدة حقيقية أو نسخة منها.

## ما تغطيه التجربة

الاختبارات في `SmartSchoolAPI.Tests/SchoolMigrationRecoveryTests.cs` تنشئ ملفات SQLite مؤقتة منفصلة لكل اختبار، وتفعّل المفاتيح الأجنبية وWAL، وتبدأ من ترحيل `20261009120000_AddRefreshTokens` ثم تطبق `20261027162508_AddExplicitSchoolOwnership` باستخدام EF Core الفعلي. تحتوي البيانات الاصطناعية على مدرستين وثلاثة طلاب ومعلمين اثنين ودورتين وشعبتين وثلاثة تسجيلات ورابطَي ولي، وسجلات حضور وسلوك وقرآن وسجل تدقيق ورمز تجديد اصطناعي. أحد الطلاب مسجّل قديمًا في المدرستين، والولي المرتبط بالمدرسة الأولى مرتبط أيضًا بالطالب الآخر؛ الروابط صالحة من جهة المفاتيح الأجنبية لكنها متعارضة دلاليًا، ولا تثبت الملكية.

1. **الترقية والنسخ والاستعادة:** بعد التحقق من وجود WAL غير فارغ، تنسخ `SqliteConnection.BackupDatabase` القاعدة إلى ملف مستقل قبل الترقية. يُقارَن محتوى الأعمدة القديمة والروابط عبر جداول البيانات الـ18 وتاريخ ترحيلات EF السابق، قبل الترقية وبعدها وبعد استعادة النسخة إلى ملف ثالث؛ لا تُستبدل القاعدة الأصلية. تُنفّذ `PRAGMA integrity_check` و`PRAGMA foreign_key_check` على الأصل قبل الترقية وبعدها، وعلى النسخة المستعادة. تتحقق التجربة من بقاء ملكية الجداول الخمسة الجديدة فارغة ووجود مفاتيحها الأجنبية إلى المدارس، ومن عدم ظهور البيانات القديمة عند استعلام `SchoolScope` بهويات اصطناعية للمدير والمعلم والولي، مع بقاء الملف الأساسي للطالب متاحًا لنفسه وظهور سجلاته للمشرف العام.
2. **تراجع بلا تعارضات جديدة:** ترحيل القاعدة الاصطناعية إلى الأعلى ثم العودة للترحيل القديم، ومقارنة الأعمدة القديمة والروابط وفحص سلامة القاعدة والمفاتيح الأجنبية. هذا لا يثبت أمان التراجع بعد إدخال ملكيات أو سجلات جديدة: إزالة أعمدة الملكية تفقد قيمها حتى إن نجح التراجع.
3. **تعارض التراجع والاستعادة:** بعد الترقية تُحاكى تسوية ملكية وإضافة حضور جديد مباشرةً بـSQL في بيانات اصطناعية؛ هذا ليس مسارًا تنفّذه API ولا أداة تسوية. وجود سجل قديم بلا مدرسة وسجل جديد للطالب والتاريخ نفسيهما مسموح بالفهرس الجديد، لكنه يخالف فهرس `(StudentId, Date)` القديم. يتحقق الاختبار من فشل التراجع بقيد الفرادة، ثم يستعيد نسخة ما قبل الترقية إلى ملف مستقل ويقارن بياناتها ويفحص سلامتها. لا يفترض الاختبار ذرّية عملية التراجع الفاشلة، ولا يواصل العمل على القاعدة التي فشل تراجعها.

استعادة نسخة ما قبل الترقية تعيد تلك اللحظة فقط: **أي تسوية أو كتابة بعد النسخ ستغيب عن القاعدة المستعادة**. في الاختبار الثالث يظهر ذلك في فقدان سجل الحضور الاصطناعي اللاحق. لا يوجد تنفيذ لاستعادة أو دمج هذه الكتابات.

## النتائج والأوامر

- أمر CI الفعلي: `dotnet test SmartSchoolAPI.Tests/SmartSchoolAPI.Tests.csproj --configuration Release --no-build --logger "trx;LogFileName=api-tests.trx" --results-directory "$RUNNER_TEMP/api-test-results"`، ويتبعه حارس `scripts/assert_dotnet_test_results.py` للتحقق من عدد الاختبارات ونجاح الاختبارات المحددة بالاسم.
- [CI لطلب السحب 40545573140](https://github.com/mamourgroupe-ctrl/SmartSchool/actions/runs/40545573140) على `bd16688` بنى API واختباراتها، وطابق migrations مع النموذج وطبّقها، ونفّذ **84/84 اختبار .NET بنجاح**، مع تحقق عشرة اختبارات بالاسم، بينها اختبارات التجربة الثلاثة. نجحت مهمتا Python وExpo. يعني نجاح اختبار التعارض أنه لاحظ فشل التراجع المتوقع ثم تحقّق من استعادة النسخة المنفصلة، لا أن التراجع نجح.
- محليًا نجح `/tmp/smartschool-venv-probe/bin/python -m pytest -q backend/tests/test_ci_test_results.py`: عدد **12 اختبارًا** لحارس TRX. هذه بيئة Python 3.11 جزئية وليست بيئة CI الكاملة.
- للتحقق من هذه المجموعة فقط عند توفر .NET 10: `dotnet test SmartSchoolAPI.Tests/SmartSchoolAPI.Tests.csproj --configuration Release --filter 'FullyQualifiedName~SchoolMigrationRecoveryTests'`. هذا أمر لإعادة التجربة، **لم يُنفَّذ محليًا** هنا لعدم توفر SDK.
- فحص محلي تمهيدي مستقل بـPython SQLite استخدم مخططًا مترجمًا يدويًا من migrations للتحقق من إدخال البيانات واستعلامات المقارنة: نجح إدخال 18 جدولًا، و`integrity_check` أعاد `ok` و`foreign_key_check` لم يُرجع صفوفًا. هذا ليس تنفيذ EF ولا يحل محل CI.

## حدود الدليل

- التجربة صغيرة ومحددة بـSQLite وملفات مؤقتة نظيفة؛ لا تغطي أحجامًا أو نسخًا مخصصة أو triggers أو views أو تعديلات schema خارج migrations، ولا أعطال الطاقة أو التوقف في منتصف الكتابة أو التشغيل المتزامن أو مفاتيح التشفير أو إعدادات تخزين الإنتاج أو زمن الاستعادة. المقارنة تشمل الأعمدة المحددة صراحةً في الاختبار لا تطابقًا بايتًا ببايت ولا كل إعدادات SQLite.
- اختبار الحجر يستدعي خدمة النطاق مباشرةً بـ`ClaimsPrincipal` اصطناعي، وليس اختبار تسجيل دخول أو HTTP جديدًا. توجد اختبارات HTTP منفصلة في `SchoolIsolationRegressionTests.cs`؛ ولا تثبت الاختبارات وحدها جميع حالات الصلاحيات الممكنة.
- `BackupDatabase` في التجربة ينسخ SQLite بما في ذلك WAL؛ **لا يُفترض أن نسخ ملف `.db` وحده يكفي أثناء نشاط WAL**. لا توجد هنا أداة تشغيل أو إعدادات لحفظ النسخ وإدارتها أو استعادتها في الإنتاج.
- لم تُفحص قاعدة إنتاجية، ولم تُختبر استعادة على بنيتها، ولم تُعتمد مدة توقف أو نقطة استعادة أو سياسة وصول. لا يُسوّى أي سجل أو يُعاد نسبه تلقائيًا اعتمادًا على هذه التجربة.

## قائمة مراجعة بشرية مقترحة قبل الدمج والإطلاق

هذه عناصر معلّقة على أشخاص مخوّلين، وليست خطوات أُنجزت:

- [ ] مراجعة أمنية بشرية للتغييرات ونتائج اختبارات الأدوار والروابط المتعارضة وسياسة المشرف العام، ثم اعتماد المرحلة 1 قبل الدمج.
- [ ] حصر نسخة SQLite الفعلية وحالتها والـschema والتعديلات المخصصة وحجمها، وتحديد مسؤول التغيير والخصوصية ونافذة إيقاف الكتابات وخطة تواصل وتعافٍ معتمدة.
- [ ] اعتماد طريقة نسخ متسقة مع WAL، تخزينها محميًا وخارج النظام، وتجربة استعادتها في بيئة معزولة مكافئة مع فحوص السلامة والمفاتيح الأجنبية وتاريخ الترحيلات ومقارنات مناسبة؛ لا تسجَّل بيانات أشخاص في نتائج الفحوص.
- [ ] تجربة الترحيل على بيانات آمنة ممثلة للبنية والحجم والحالات المتعارضة، ثم تقدير عدد الصفوف المحجوبة في الجداول الخمسة وتحديد أثر توقف المدارس عن رؤية البيانات القديمة.
- [ ] اعتماد إجراء مفصّل ومسؤولين لتسوية الطالب والمعلم والدورات والشعب والتسجيلات والأولياء وكل سجل على حدة، مع إثبات الملكية والتدقيق البشري؛ لا توجد أداة جاهزة لذلك حاليًا.
- [ ] اعتماد نقطة التعافي وحدود فقد الكتابات وكيفية التعامل مع التغييرات اللاحقة للنسخة قبل أي ترقية. عند فشل التراجع، أوقف الكتابات واحفظ الحالة للفحص، واستعد واختبر نسخة منفصلة؛ لا تفترض نجاح `Down` أو تستبدل قاعدة حية قبل قرار معتمد.
- [ ] تحديد شروط منع الإطلاق ومعايير إعادة الخدمة والاتصالات والتصعيد واختبارها على البيئة الفعلية. نجاح هذه التجربة وحده لا يجيز الإطلاق.
